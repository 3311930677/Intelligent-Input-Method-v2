# ADR 0010：版本化插件存储与原子激活

- 状态：P3C 已采用
- 日期：2026-08-01

## 背景

插件更新不能覆盖正在使用的版本，也不能把运行数据混入可执行目录。安装期间还可能发生磁盘写入失败、进程退出或系统重启，因此“文件已经解包”“版本已经发布”和“版本已经激活”必须是可区分的状态。

## 决策

Windows 插件存储采用以下固定布局：

```text
<root>/
  staging/<transaction>/
  versions/<plugin-id>/<version>/
  records/<plugin-id>/<version>.record
  active/<plugin-id>.record
  data/<plugin-id>/
```

1. `staging` 只接收安装事务创建并完成验证的暂存目录。低层发布 API 接受“已预验证暂存目录”作为前置条件；它本身不是信任授权，也不得用于跳过包签名、证书链或解包复验。
2. 版本目录只新增、不覆盖。暂存目录必须是同一存储根下 `staging` 的直接子目录，并通过同卷目录重命名原子发布到 `versions`。
3. 每个版本有一份不超过 1 KiB 的封闭字段记录，绑定插件 ID、版本、包清单 SHA-256 和已验证发布者证书 SHA-256。记录文件通过同目录新建临时文件、刷盘和原子替换写入；记录文件及父目录不得为重解析点。
4. `active/<plugin-id>.record` 是唯一活动版本指针。激活和回滚只原子替换该记录，不使用符号链接、junction 或目录覆盖。切换前重新验证目标 manifest 和版本记录的一致性。
5. `data/<plugin-id>` 独立于版本目录，安装、更新和回滚均不得替换或删除它。运行时写入可执行版本目录的限制将在 PluginHost 沙箱切片中强制实施。
6. 发布版本记录成功但活动记录替换失败时，该版本保留为“已安装、未激活”，旧活动记录不变。崩溃也可能留下无活动引用的已发布版本；后续恢复逻辑只能依据严格记录进行识别，不得递归清理宽泛路径。
7. 版本目录在存储语义上不可变。当前切片以“不覆盖既有版本”和受控 API 保证该约束；文件系统 ACL 与运行进程写权限收紧留给 PluginHost 安装集成切片。

## 影响

更新和回滚不再依赖覆盖或复制正在使用的目录，插件数据可跨版本保留。一次失败最多产生可审计的未激活版本或精确暂存目录，不会把部分写入版本设为活动状态。

正式安装入口仍需把同一包快照的信任验证、暂存解包、输出复验和本 ADR 的发布步骤组合成单一高层事务；在该入口完成前，低层发布函数不面向 UI 或外部调用方。

## 回滚

将活动记录原子切换到仍然存在且记录有效的旧版本即可回滚。删除存储实现不会影响输入引擎；物理清理旧版本属于后续显式维护操作，不在激活事务中隐式执行。
