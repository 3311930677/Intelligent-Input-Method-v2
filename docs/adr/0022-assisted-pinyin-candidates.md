# ADR 0022：不完整拼音补全与有界纠错候选

- 状态：P3 后体验优化已采用
- 日期：2026-08-02

## 背景

原全拼解析器能够标记末尾的不完整音节，但候选生成器会丢弃包含该标记的全部路径。因此单声母 `b`、`nih`、`zhongg` 等输入没有候选。完全无法按合法音节切分的误触、漏字、多字和相邻字母颠倒也不会进入词典查询，候选窗只能持续显示加载省略号。

## 决策

1. 不完整拼音只补全解析路径末尾已有的音节前缀，不改写已完成音节。候选路径仍限制为最多 32 条，并优先保留补字符更少、音节更少的补全。
2. 当输入不存在任何完整拼音切分时，启用最多一次编辑的纠错：相邻字母颠倒、漏一个字母、多一个字母、QWERTY 相邻键替换，以及 `l/n`、`f/h` 常见声母混淆。少于 3 字节、超过 32 字节或含显式单引号边界的输入不做纠错。
3. 合法完整拼音不预生成纠错候选，避免 `nihao` 混入由一次编辑得到的 `niao`，同时保护正常输入延迟。候选生成器仍把纠错视为无精确词典命中时的后备路径，防止其他输入方案把纠错结果混入精确结果。
4. 补全路径按基础惩罚 1,500 分、每个补入字符 750 分降权；纠错路径每次编辑降权 6,000 分。只要存在精确候选，第一候选必须来自精确拼音；相同文本去重时也优先保留更精确的来源。
5. 所有解析和查词继续在 Core Service 候选工作链路执行，TSF 按键线程不扫描词库、不加载模型。协议暂不增加纠错标记；来源类型只在引擎内部用于排序与测试。
6. TSF 必须接收并处理空候选响应。请求尚未完成时显示 `…`，已完成但无结果时显示“无候选”，不得把空响应丢弃后无限保留加载状态。

## 结果

完整词库验证中，`b` 返回“把/不/吧”，`nih` 包含“你好”，`zhongg` 首选“中国”；`niaho`、`nihap` 首选“你好”，多输一个字母的无效切分也包含“你好”。`zhonggu` 仍以精确的“中古”为第一候选，同时提供补全的“中国”。精确输入的完整词库基准与改动前处于同一延迟量级；辅助输入的独立数据见 `docs/benchmarks/assisted-pinyin-2026-08-02.md`。

## 已知边界

- 本决策不是通用编辑距离或语言模型纠错；两处及以上错误、非相邻任意替换和显式音节边界内的纠错均拒绝。
- 能被完整合法拼音切分的输入不做纠错，即使该切分最终没有用户想要的词；后续若要放宽，必须采用“精确查词为空后再惰性纠错”的两阶段接口并重新测量延迟和误触发率。
- 补全候选当前不在候选窗标注来源。若未来增加标记，需要扩展候选协议并同时兼容 TSF UI Element 与独立候选 UI 进程。

## 回滚

移除 `ParsePath` 的匹配来源、补全/纠错扩展和相应候选惩罚，即可恢复只接受完整拼音路径的行为；词库格式、用户词频、IPC 消息和配置文件无需迁移。空候选状态反馈可以独立保留。
