# ADR 0008：插件包与信任基础

- 状态：暂定，随 P3C 安全验证冻结
- 日期：2026-08-01

## 背景

插件包是直接面向不可信输入的供应链边界。TSF 和 Core Service 必须在插件损坏、恶意或不兼容时继续提供基础输入，因此包解析、安装和执行必须拆成相互隔离的阶段。

## 决策

1. 保留总控提示词中的 `.owopkg` 和 `manifest.json`，采用受限 ZIP 兼容容器。P3C 预检器仅解析元数据，不解压；拒绝 ZIP64、多卷、加密、数据描述符、注释、扩展字段、符号链接、重叠条目、非 Store/Deflate 算法和超出文件数、大小或压缩比限制的包。
2. Manifest v1 使用封闭字段集合。只接受严格三段数字版本、反向域名式小写 ID、API 1、进程运行时、安全相对路径和枚举权限。解析成功不代表包可信或可执行。
3. 网络默认关闭，v1 解析器直接拒绝 `network=true`。未来开放网络需同时具备用户授权、运行时强制和可审计撤销，不能只相信 manifest 声明。
4. 正式安装默认要求完整性与发布者信任同时通过。签名必须覆盖规范化 manifest 和每个包文件的路径、大小、SHA-256；不得仅签名一个可被替换的 `signature.json`。
5. 解包必须在隔离暂存目录完成，拒绝绝对路径、驱动器路径、`..`、链接/重解析点、重复规范化路径、设备名、大小或文件数超限，再以原子目录切换发布。
6. 插件只能在 PluginHost/独立插件进程执行，不加载进 TSF 或 Core Service。运行时不继承多余句柄，使用固定绝对入口和安全 DLL 搜索策略。

### `OwOPackageInventoryV1` 规范化摘要

规范化字节流以 ASCII `OwOPackageInventoryV1` 和 NUL 开始，随后是小端 `uint32` 条目数。除精确根路径 `signature.json` 外，条目按 UTF-8 路径原始字节升序排列，每项依次写入：小端 `uint32` 路径字节数、路径字节、小端 `uint16` 压缩方式、小端 `uint32` CRC-32、小端 `uint64` 压缩尺寸、小端 `uint64` 解压尺寸、64 个小写 ASCII 字节的压缩数据 SHA-256。最终对完整字节流计算 SHA-256。

排除 `signature.json` 只解决签名自引用，不意味着忽略它：后续验证器必须严格解析该文件，并用其中的签名验证上述摘要。摘要相同只表示规范化内容相同，不表示发布者可信。

## 影响

当前实现可在没有压缩库和证书依赖的情况下验证 manifest 与 ZIP 元数据中最危险的输入面，同时不会制造“已经支持安装或执行”的假象。解压库、证书来源、开发者模式和自动更新源仍可替换，但容器限制和默认拒绝原则保持不变。

## 回滚

`owo_plugin` 当前没有接入任何运行进程。删除该库、测试和 P3C 文档即可完整回滚，不影响输入引擎、配置、ModelHost、Core Service 或 TSF。
